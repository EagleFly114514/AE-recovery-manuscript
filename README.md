# Conditional functional recovery in autoimmune encephalitis

Analysis software for conditional functional recovery, paired functional transitions, missing-outcome assessment and auxiliary prediction comparisons. Candidate selection, tuning and parameter estimation use development data. Temporal evaluation follows specification freezing.

This repository distributes software, method settings and input-field definitions. Clinical records, aggregate study results, model predictions, fitted objects, manuscripts and figure files are supplied separately under the applicable access arrangements.

## Installation

Use Python 3.12 and an isolated environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r environment/requirements-analysis.txt
```

## Code checks

```powershell
python reproduce.py --stage check-code
python scripts/verify_checksums.py
```

Code checks use mathematical examples generated in memory. They do not require clinical data.

## Analysis

Place an authorised input bundle and its SHA-256 manifest outside the repository. Required files and fields are documented in [INPUTS.md](INPUTS.md). Use a separate output directory:

```powershell
python reproduce.py --stage clinical --inputs D:/authorised/analysis_inputs --out D:/authorised/run --jobs 4
python reproduce.py --stage all --inputs D:/authorised/analysis_inputs --out D:/authorised/run --jobs 4
```

Individual stages are `clinical`, `primary`, `precision`, `multiple`, `icu`, `legacy`, `posthoc`, `tables` and `figures`. The full sequence runs them in that order. `smoke` shortens only the primary resampling procedure and is for execution checks. Primary and precision draw counts are in `configs/analysis_plan.json`; the historical comparator settings are in `configs/legacy_spec.json`.

`posthoc` uses predictions generated by `primary`, or an authorised prediction directory passed with `--saved-predictions`. Numerical outputs can include individual predictions and linked records. The entry point keeps input and output directories outside the software repository.

The PowerShell wrapper exposes the same stages:

```powershell
.\run_reproduction.ps1 -Stage clinical -Inputs D:/authorised/analysis_inputs -Out D:/authorised/run -Jobs 4
```

## Software organisation

| Component | Purpose |
|---|---|
| `code/clinical.py`, `scripts/clinical_recovery.py` | Conditional outcomes, paired transitions and sensitivity populations |
| `code/functional_baseline.py` | Development-only candidate selection and the simple clinical baseline |
| `code/history_marginalized.py`, `conditional_history.py`, `risk_refinement.py` | Frozen history/function comparisons |
| `code/evaluate.py`, `missing_outcomes.py` | Paired evaluation, resampling and missing-outcome scoring |
| `code/legacy_*.py`, `scripts/run_legacy.py` | Historical feature comparisons and nested resampling |
| `code/posthoc_clinical.py`, `posthoc_prediction.py` | Adjusted clinical comparisons, calibration and direct clinical comparators |
| `code/publication_tables.py`, `scripts/make_supplement_tables.py` | Tables calculated from runtime outputs |
| `scripts/make_figures.py` | Figures calculated from runtime inputs and outputs |
| `tests/test_public_code.py` | Packaging, resampling and transition checks |
